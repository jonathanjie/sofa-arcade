## Clocks and real host stalls

Only the time source and timer delivery are controlled in the fixture. `ManualClock.advance` invokes scheduled callbacks in order, and `jump` delivers overdue callbacks at the late time. The real coordinator still schedules `tick`, and both clients still send actual commands and input frames over real sockets. The unit coordinator uses an independent simulated game. Native protocol integration calls `startLanServer`, uses the production SQLite/GO1 coordinator bundle, observes the real scheduler callback, and receives pause over an authenticated socket. The throwing-observer real-timer case verifies the default timer wiring.

A busy Mac can cause this pause during real play. With no injected clock, the Node coordinator uses real `performance.now()` and `setTimeout`. In a playing or countdown room, an unblocked scheduler callback with a gap greater than 250 ms queues a `host-stall` pause before catch-up. It clears steering, advances the run epoch, persists and broadcasts the new state. A 350 ms Node callback delay can therefore interrupt active play and require both gardeners to ready again. A stall confined to the TV browser is a different process. On this Mac the rendered journey reached the campaign and then failed with `Unexpected shared pause during campaign: host-stall`. That is an observed product behavior from the real-clock gate. This review leaves its production threshold unchanged. [LAN clock wiring](../server/lan.mjs#L190), [default clock and active phases](../server/realtime/gravity-orchard/index.mjs#L20), [250 ms limit](../server/realtime/gravity-orchard/lib/protocol.mjs#L8), [tick check](../server/realtime/gravity-orchard/index.mjs#L295), [pause and durable publication](../server/realtime/gravity-orchard/index.mjs#L271), [TV pause copy](../ui/games/gravity-orchard/tv/index.mjs#L45).

Lowering 250 to 200 made the coordinator and fixture fail at their playable-window assertions. Using an infinite threshold made them fail to observe the late pause. The integration gate initially survived the source-only edits because it imports `server/runtime/gravity-orchard-dependencies.mjs`. Repeating both changes in that exact runtime made the integration test fail at the sub-threshold assertion and at the missing TV pause respectively. Every mutation was restored byte for byte.

## Product fix proposals

1. **SSE retry after stop.** `subscribeRoom` tests `stopped` before it calls the offline callback. The callback can call `stop()` before `retryTimer` exists. Recheck `!stopped && !terminal` immediately after the callback and before computing or scheduling backoff. Keep the existing early return in `connect`. Remove the expected-failure condition when the test observes zero timers, one fetch and no callbacks after offline. [Transport cleanup and scheduling](../ui/transport.mjs#L140)
2. **TV accepts contradictory stage scores.** Enforce `stars === [0, 1, 1, 2, 3][ordersCompleted]` in `readPublicView` after validating field bounds, before returning the owned snapshot. Use a browser-safe rule that agrees with the engine and stays inside the delivered module graph. Reject the complete view so that neither the event cursor nor the scoreboard changes. Remove the Playwright expected failure when the malformed frame leaves rows, totals and finish cues unchanged and the next valid frame renders. [TV field validation](../ui/games/gravity-orchard/tv/public-view.mjs#L42), [engine scoring](../games/gravity-orchard/engine.mjs#L299), [TV update and effects](../ui/games/gravity-orchard/tv/index.mjs#L282)
